# 传统标签：catalog 的普通字段

日期：2026-11-07（Asia/Taipei）。按用户最新要求，在模型 catalog 和详情页增加一个普通字段，不放在型号名称旁，也不作为重要展示元素。已确认名单与简化维护方式保持不变。本版已实现并完成发布前本地验证。

## 字段

字段名为 `legacy`，布尔类型，与其他模型属性并列：

```json
{
  "id": "nace-ai/drex-v1.5",
  "name": "Drex 1.5",
  "legacy": true
}
```

- `true`：当前标为传统。
- `false`：当前未标传统，不表示主推、最新或能力认证。
- 旧数据没有该字段时按未提供处理；读取和显示不要求旧客户端升级。

不引入 latest 字段，不合并或替换官方 status、deprecated、retired 字段。

## 页面

**Catalog 列表**：增加普通的“传统型号 / Legacy”列，排在现有属性列后部，显示“是／否”或 Yes / No。与普通属性列使用相同字号和颜色，不放在名称旁，不置顶、不固定、不加醒目颜色，不设置特殊排序优先级。

**模型详情页**：在现有 Facts 属性区增加“传统型号 / Legacy”一项，放在 Release、Updated 附近的普通属性位置，显示“是／否”或 Yes / No。字段未提供时显示与其他缺失属性一致的占位符。不在标题、副标题、摘要、徽标区或独立卡片重复强调。

本功能不增加分组切换、筛选、默认展示变化、折叠或隐藏，不改变现有排序、搜索、列表成员或选择行为。

## 维护与数据接入

正式维护入口为 [`legacy-models.json`](../config/legacy-models.json)，保留 `schema_version`、`models` 和必要的 `provider_overrides`，已从确认名单导入 673 个共享版本及 1,255 条精确服务覆盖项。增删名单或修改服务布尔值即可维护；历史交给 Git，不要求填写理由、证据、替代型号、审核时间或单条修订。

构建时把名单结果合并成目录视图中的 `legacy` 字段，页面直接展示该属性。共享型号按具体共享版本判断；provider 服务视图按精确服务覆盖项优先。某条记录包含多个协议时，不把单协议决定上提为所有服务的共同结果，也不从相似名字或模型 ID 猜关联。

当前公开目录及 C/P/N 合同存在严格 schema，不能把新增字段宣称为旧消费者无损兼容。现已同步类型、schema 和正反例：网站内部使用合并后的目录；`/catalog.json`、`/models.json` 和 `/api.json` 通过显式 `include=legacy` 提供新字段，原默认响应结构保持兼容。该参数是接口兼容细节，不增加页面操作。v1 provider 字段按原解析器首个协议的完整身份计算，已有 scope 差异继续按相应服务记录表达，不为字段另建标签服务、独立 manifest 或发布流水。

标签只作为模型资料，不修改执行模型 ID、请求地址、路由、调用资格或任务配置，不触发自动换模。CogineWork 接入通过本仓库合同和纯投影交付，不在这里改客户端。

## 交付与检查

实现范围限于简化名单配置、catalog 字段合并与对应兼容输出、列表普通列和详情普通属性项。检查已定版型号及服务范围不遗漏，true/false/未提供三种显示符合约定，provider 例外有效，原成员、排序、搜索、调用及原接口合同不受影响。

本轮未修改上游模型资料、C/P/N 指标、执行配置或生产数据。固定 Bun 1.4.4 下类型检查、schema 检查、241 项测试、网站构建、上游 validate 和固定基线 v1:check 通过。原名单及配置预览未变；公开发布结果需单独回读验证。
