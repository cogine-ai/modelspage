# Modelspage：直觉设计走查

2026-10-27。原则：通过对象、布局、分组、控件和反馈表达含义，减少解释性规则；必要的字段名、单位、状态仍须保留。

本轮实际查看 v3 全七张最终图，并在当前本地画廊重新截图；另检查现有 Web 的模块、数据合同和价格聚合代码。当前 v3 是静态原型，`packages/web` 仍保留原基线实现，两者不是同一份已运行产品。

## 1. 默认价格缺少报价归属，容易形成“这些模型都免费”的直觉

**位置／任务：** Models 的 Input from／Output from，用户比较使用成本。

**现状：** 七行均显示 $0.00；同一模型的 Provider 详情却显示 from $0.15／$0.60。聚合分别从所有已知输入／输出字段取最小值，零值还包含套餐边际 token 价和按调用／Credits 计费记录。原始数据并没有算错，但两列金额无法直接回答“我选哪家、以什么口径获得这个报价”。用户必须读数据说明才能纠正界面造成的直觉。

![本轮 Models 截图](/Users/kiedis/Coding/AI/modelspage/.modelspage/ux-intuition-audit-20261027/01-prices.png)

**改法：** 让成本比较以真实 Provider 报价为单位，金额紧邻可识别的提供者／计费方式。模型级若无法给出同口径的可用报价，应由明确的报价入口承接，保留原始零值在资料明细。不能随意拿一家付费价替换真实零值，也不能追加“0 不等于免费”的长说明来弥补缺少归属。

**建议验收：** 给定模型，首次使用者无需阅读规则即可指出哪家、什么计费方式、多少钱。此任务本轮未执行。

依据：`packages/web/src/render.tsx:212`、`.modelspage/prototype-v3/DATA-NOTES.md:13`。

## 2. 两种 ID 都提供复制，但用于调用的那个没有成为清楚的主动作

**位置／任务：** Model 详情标题下 ID 与 Provider 表的 API model ID，用户取得调用参数。

**现状：** 标题下 `deepseek/deepseek-v4.1-flash-1017` 无字段标签且有显眼复制；原厂行的实际请求 ID 是 `deepseek-flash`，也有相似复制图标。界面把内部目录身份与调用身份放在相似操作层级，新访客要先懂 canonical／Provider 路由区别才能选对。这里没有断言图中的复制实现错误。

![本轮详情截图：顶部目录 ID 与中部请求 ID](/Users/kiedis/Coding/AI/modelspage/.modelspage/ux-intuition-audit-20261027/02-id-copy.png)

**改法：** 目录身份放到较轻的 `Catalog ID` 资料组；Provider 行的 `API model ID` 与复制按钮成为明确的调用动作。保持所有 ID 原值和复制所见内容，不用一段“两者不同”的注意事项补救。

**建议验收：** 指定 DeepSeek Provider 后取得 `deepseek-flash`；同时需要目录身份时仍能找到它。此任务本轮未执行。

依据：`cogine/docs/data-contract.md:32`。现有基线 `render.tsx:1138` 还存在显示 ID 与复制组合值不一致的遗留项；v3 已有“所见即所复制”的设计要求，该实现遗留不重复当作 v3 新发现。

## 3. Data 没有把“一次下载”和“接入每日更新”组织为两个清楚任务

**位置／任务：** 数据集行的 JSON／Copy URL 与下方 Copy manifest URL，用户或 agent 获取数据。

**现状：** 行级取数动作和详情级 manifest 复制并存；页面没有把两个地址分别对应的用途建立起来。用户需要先学 manifest→revision，或复制后查看地址，才能选择持续更新入口。静态图不能证明行级 Copy URL 具体指向什么，结论限于画面缺少角色区分。

![本轮 Data 截图：两组获取动作](/Users/kiedis/Coding/AI/modelspage/.modelspage/ux-intuition-audit-20261027/03-data-actions.png)

**改法：** 以短动作和分组清楚区分 `Download JSON`（当前版本）与 `Connect updates`（manifest）。版本、Schema、原始路径继续保留在相应资料中；不把内部版本合同写成先读教程。这是组织现有资源的改法，不新增 API。

**建议验收：** 分别完成一次下载和持续取最新，两种任务能直接选对入口。此任务本轮未执行。

依据：`cogine/docs/data-contract.md:7`。

## 4. 手机的能力分和日期失去了字段锚点

**位置／任务：** 手机列表行内 `45.1 AA ↗ · 2026-10-17`，用户比较能力与新旧。

**现状：** 主 P 有 Popularity · 7d 表头，但次行只留下来源缩写和裸日期。首次只看手机页的人必须知道 AA 是什么，还要猜日期表示发布还是更新；需要先打开来源或记住桌面列义。压缩文字同时丢掉了必要含义。

![本轮手机截图：主指标有表头，次行缺少字段锚点](/Users/kiedis/Coding/AI/modelspage/.modelspage/ux-intuition-audit-20261027/04-mobile-fields.png)

**改法：** 为次要指标建立一次性的短字段表头／视觉分栏，让能力分与日期分别对齐 `Intelligence`、`Released`；AA 继续作来源标记，避免每行重复说明或换成猜义图标。具体窄屏布局需要下一版实际渲染验证。

**建议验收：** 首次仅看手机页，能说出 45.1 衡量什么、该日期是什么日期，不需先看桌面。此任务本轮未执行。
