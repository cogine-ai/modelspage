# 基于上游源码的 Web 复现

本轮按用户确认的边界实现：保留 models.dev 原网站功能，在之外增加独立排名页和数据入口。v4 图表图只是 Rankings 页探索，不再替代 Models 页。站点未写入项目宗旨或大段规则文案。

## 输入与范围

- 原网站源码：`packages/web`，本轮开始时与固定上游 `4f1231e6bf72d5fa66dc1163599eaaedb607faab` 无差异；上游 HEAD 查询确认默认分支仍为 dev。本轮没有同步或运行新上游部署。
- 原目录、价格、N：当前固定源码及原生成器；模型日期直接复用，不加人工核验白名单。
- 本地 C/P Bundle：`4be1119eda7d0084601a8d1dfdb14abb86ec30124b72f3e2885612c9e92b118d`，其 models.dev 数据来源为较新的 `8f6f1503f1082188e5fe150b3f36260f1169b9cf`。网页 JSON 分别保留 canonical_source 和排名 source_revisions，不声称二者同版本。
- 展示 614 个 canonical 模型、232 个 Provider；C 199、P 54、有效日精度 N 612；C/P 两项均有的模型 41 个。Provider 专属、未关联 canonical 的成员保留在原目录和 Provider 页，不猜测成 canonical。
- P 使用已有的 60/30/10 并集结果和 UTC 2026-10-20 至 26 窗口；没有重新采集或把当前日期冒充来源日期。C 为同一 AA v4.3 profile，保留每模型实际配置。
- `/rankings.json` 是 local-preview 投影，不替代正式 `/v1/` 合同；没有进行网站生产部署或改变既有生产用途校验。

## 实现

Models、Providers、Labs 及详情、全局搜索、表格排序、复制逻辑和原 API 复用原代码。新增代码在 `cogine/web/`，上游文件只有导航、入口、额外 JSON 输出和两处等价类型修正。品牌入口为 Modelspage，保留 LICENSE 与上游来源。

`/rankings` 提供 P/C 横向条形图、N 日期列表、C×P 散点和精确表格。过滤前使用全量总序；缺失值不补零；P/C 轴上限分别是全量快照决定的 20 / 60，不随筛选变动。点击分值或点查看来源、权重、已观测天数和配置。数据页分别下载原完整目录和排名投影。

发现并修正：全量目录下载原来没有 `type=all`，少8个非默认类型模型；现在下载与计数一致。条形原先与数值标签同处 flex 会被压缩，现条形不收缩、数值绝对定位。散点只直接标识 C/P 代表模型，避免密集区域标签叠压；手机散点使用独立视口几何与相同数据尺度。来源配置展示为实际配置名称，原始身份仍在 JSON。

测试过程另有两项已澄清：首次自设 TMPDIR 未创建导致测试夹具失败，创建后重跑；原日报测试用任意子串 `999` 检查泄漏，偶然命中随机 Git hash，现改为检查确切 score 字段和 snapshots 属性，没有放宽实际数据泄漏检查。

开发服务器的上游 HMR WebSocket 警告未作为产品错误修补；最终提供的是静态构建预览，不含该 HMR 链路。静态页面的浏览器应用错误检查见本地截图/控制台记录，不把构建、HTTP 200 或本地预览等同于生产验收。
