# Modelspage Web 走查与设计方案

状态：设计分析，尚未修改正式 Web。2026-10-27；以本轮实际访问的 models.dev 为体验基线，并对照仓库现有 `packages/web` 与 C/P/N 合同。

## 设计决定

保留 models.dev 已经成立的模型目录、Provider 目录、Lab 目录和详情关系。将 C/P/N 放进这些用户正在看的对象中；数据集有一个稳定的 Data 入口。主屏直接呈现可操作的数据，不承担介绍产品宗旨或教授内部规则的任务。

本文件是内部设计依据，不是待搬到网站上的文案。页面不放使命宣言、工作流说明、核验过程、身份继承规则或每行兜底解释。必要的控件名、字段名和单位保留：用「能力」「热度」「最新发布」表达操作，不要求用户先学习 C/P/N 缩写，也不改成三枚需要猜义的图标。

## 一套页面结构

主导航保持 **Models / Providers / Labs / Data**。前三项是浏览对象，Data 是获取数据的入口。品牌与搜索保持清楚，不增加首屏介绍、营销 hero、更新宣传卡或排行榜宣传区。

| 页面 | 用户在这里完成什么 | 首屏内容 | 按需出现 |
| --- | --- | --- | --- |
| Models | 找到、排序、缩小模型范围 | 搜索、排序切换、少量筛选、模型表 | 更多列、更多筛选、指标详情 |
| Model | 看模型，再比较提供者 | 名称／ID、紧凑指标行、Provider 比较 | 来源、配置、原始规格、历史版本 |
| Providers | 找提供者 | 名称、模型数、API、Docs | SDK、完整元数据 |
| Provider | 在该提供者内找模型／复制 ID | API、Docs、该 Provider 的模型表 | 协议、来源原名、精确规格 |
| Labs / Lab | 按研发机构浏览 | 名称、计数、模型表 | 机构描述、其他资料 |
| Data / Dataset | 预览、下载、接入数据 | 数据集列表及实际下载动作 | 字段、版本、Schema、来源与方法 |

Providers、Labs 不设计没有数据依据的「综合得分」。它们的详情直接复用模型表，不另造一套概念或操作方式。模型名、Provider 官方名称和所有 ID 保留原貌，不为界面统一而重命名。

## Models：在原目录里增加排名

### 默认表格

首列合并模型名称、Lab 小标识与低对比 ID，模型名称是进入详情的链接。后续默认列依次为 **热度、能力、发布、上下文、价格、Providers**。根据实际窗口收起低频列，不能把主指标挤到屏外；展开的完整列集合仍保留上游字段。

表格上方提供三个短操作 **热度 / 能力 / 最新发布**。建议首发默认热度，并记住用户上次选择；这是同一份完整模型集合的排序视图，不是三个互相割裂的榜单。选中状态、对应列强调和表头箭头始终一致；同一次点击不产生第二套排序规则。用户改按 Context、Price 等其他列排序时，取消三个快捷操作的选中态，由当前表头显示排序方向。

搜索框就在当前表格上方，输入后筛当前列表；Ctrl K 保留为全局跳转入口。筛选从用户能辨认的 Lab、Provider、模态、上下文范围开始，其他条件进筛选面板。已选条件显示为可关闭的小项，并有一次清除动作。不要求每列都先配一个下拉框。

排序后再搜索／过滤，复用现有 C/P/N 总序。URL 保留对象、查询、筛选与排序；浏览器返回恢复原列表位置。不要在搜索后重编一个看似全站排名的新名次。

### 数值和状态

| 数据 | 默认展示 | 不采用的表现 |
| --- | --- | --- |
| C | 原始分数，表头用「能力」并带可点的 AA 标记 | 不显示无依据的 `/100` 或给不同评测画同一量表 |
| P | 热度分；表头保留短的 `7d` 标记，排序方向明确 | 不加市场份额 `%`、调用次数或误导性的逐行全站名次 |
| N | 原始发布日期；精度不足则保持原精度 | 不混用 Updated，不补造具体日 |
| 未知 | `—` | 不写 0，不在每格写一段缺失说明 |
| 已知零 | `0` 或该列正常零值格式 | 不并入未知 |
| 撤回／冲突 | 对应单元格一个短状态；点开看依据 | 不用全页警告，也不删除整个模型 |

P 未覆盖的模型仍按既定 C、N 和稳定次序显示，单元格保持 `—`。默认不插「正在按 C/N 兜底」的说明条，也不逐行标注回退规则；需要知道方法时，从同一个指标详情入口查看。C/P/N 字母只用于 Data 的字段／技术结构，不作为普通用户唯一的按钮名称。

价格表头只标一次单位，例如每百万 tokens；输入、输出的方向在表头明确。模型级最低输入价、最低输出价分别标「输入起」「输出起」，不让用户以为它们必然是同一个 Provider 的一对报价；Provider 行展示该行真实报价。点击价格即可转到提供者比较，不靠教程解释从哪里购买或调用。

## 模型详情：先判断，再选择 Provider

标题区保留模型名、Lab 与完整 canonical ID，紧凑展示能力分、热度分和发布日期。指标是可点击的数据，不做三个占据首屏的大型 KPI 卡；上游模型描述保留为低优先级资料，不用它介绍本站用途。

指标详情采用桌面侧栏／手机底部抽屉，关闭后保持原列表或详情位置：

- 能力：来源、实际 AA 模型及配置、方法版本、数据时间、其他配置；有多个实际方法时才显示方法切换。
- 热度：本批窗口，三源实际贡献，60/30/10 权重和观测日；用结构化行、日期格和数值表达。固定七日数据就显示 `7d`，不画尚未实现的 1d/30d 下拉选项。
- 发布：上游日期、精度、来源链接；需要时展开原字段。

详细方法和 JSON 在同一处继续展开，不再在首页、表尾和每个空格各写一次。展示字段直接来自现有事实与证据；不会为了设计图制造历史曲线、趋势箭头或精确调用量。

下方比较 Provider：**Provider、实际 API 模型 ID、输入价、输出价、上下文、必要功能**。这里不重复为同一个模型堆一排相同 C/P 数字；若实际配置不同，用该行配置标记或展开详情表达。Lab 在单个模型的 Provider 表中可收起，节省给价格和 ID 的空间。

复制行为必须可预测：canonical ID 旁复制 canonical ID，Provider 行里复制当前显示的 API ID。现有实现显示 `gpt-6.1-terra` 却复制 `azure/gpt-6.1-terra`，需要修正。组合标识若确有用途，放入显式的第二动作，不能复用同一无标识按钮。图标在原位置短暂变为成功状态，不弹长通知。

## Provider 与 Lab 页面

Providers 列表的 SDK Package 进入详情，API 使用等宽短行与复制按钮，Docs 是直接可点的外链。模型数可点击，进入该 Provider 已筛好的模型表。

Provider 详情保留来源模型名与精确请求 ID，不用 canonical 名称覆盖它们的版本或配置差异。没有 canonical 关联的型号也可展开自身记录，不把「不能进入全局模型页」做成死路。不从型号名称猜测缺失 C/P/N；界面只使用现有数据。

Labs 列表移走占据大部分宽度的 Description 列，优先显示模型数、Provider 数与最近发布。原描述完整保留在 Lab 详情；Lab 详情的模型表与 Models 同一套，Lab 条件已选中即可。

## Data：给新数据集一个固定扩展位置

Data 是数据集目录，数据集是一行可预览、可下载、可追溯的对象。默认显示 **名称、覆盖规模、数据时间、格式、版本、操作**；不加入「数据产品愿景」介绍或每个条目的营销段落。

现有逻辑可分为上游基础目录与 C/P/N 附加事实两类。排名事实当前实际以一个 `catalog.json` 对象分发，不能在界面上伪装成已经实现了三个独立 C、P、N API。基础目录也不能被稀疏事实包替代。真实可用的资源才提供下载按钮；未来新增数据集按同一行／详情模板加入，不随每个数据集增加一级导航。

数据集详情顺序为 **预览表 → JSON / 复制地址 / Schema → 版本与来源**。人和 agent 对同一版本取数；操作是正常链接和按钮，不要求先读一页 curl 教程。需要代码示例时，在技术详情中提供最短可用示例。

当前 `/v1/manifest.json` 与不可变 revision catalog 是已实现的合同路径，正式域名和公网站点尚未发布。完整目录接口、数据集索引和新的前端路由属于待落地设计，不能把 models.dev 的完整 `catalog.json` 与本项目稀疏 ranking catalog 当成同一个 schema。

## 手机与无障碍

390px 首屏保留品牌、搜索按钮、筛选入口与当前排序。列表每行左侧是模型身份，右侧是当前主指标，第二行用少量次要数值；更多规格进入该行详情。排名表不再要求先水平滑过整张桌面宽表才能看到主指标。需要保留横向比较的表格至少固定身份列。

搜索在手机上直接打开，不经主菜单；弹层有可点击的关闭按钮，内容区域适应动态视口。图标说明能通过点击或键盘获得，不只依赖 hover；必要短标签、读屏名称与可见焦点不属于冗余文案，应正常提供。

源码确认还需处理：搜索字符规范化保留 Unicode；输入法组合状态不把 Enter 当作选择结果；加载失败与零匹配分开；搜索结果、关闭和复制按钮有明确的 `focus-visible`。保留已有原生链接、排序按钮和 `aria-sort`。

本轮未用真机软键盘、VoiceOver 或其他读屏完整验收，也未触发真实网络错误；这些是实现后的验证项，不报告为已经通过。没有为测试改写公开网站的 CSS 或运行状态。

## 实现边界与顺序

网页继续使用完整上游目录作为基础，再叠加本项目的 C/P/N 事实。浏览页面的字段与 Data 下载内容来自同一固定版本；网页只做只读展示和既有排序投影，不在 UI 代码中重新抓取来源、猜测关联、混合评测或另算一套排序。

优先顺序：

1. Models 的紧凑表格、排序切换、表内搜索、列选择与窄屏布局；同时修复制值、焦点、关闭和中文输入问题。
2. 模型详情的指标行／指标详情、Provider 比价，复用到 Provider / Lab 的模型列表。
3. Data 目录和数据集详情，接实际 manifest／schema／下载资源。
4. 新增数据集沿用同一目录与展示模式；有实际数据和用户任务时才增加新的图表或页面，不提前造仪表盘框架。

首批验收围绕动作：找到模型、切换排序、缩小 Provider、复制眼前 ID、查看某个指标来源、取得同版本 JSON。390px 下这些动作不应先要求横向寻找按钮。短标签足以说明的地方不加解释；确需方法细节的地方只设一个主动展开入口。
